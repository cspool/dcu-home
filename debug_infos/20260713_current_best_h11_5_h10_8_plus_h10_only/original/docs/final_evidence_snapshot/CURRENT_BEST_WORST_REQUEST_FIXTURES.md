## 逐请求指标和选择规则

benchmark 原生保存的是整个分档的
`output_throughput=sum(output_lens)/duration`，没有保存原生逐请求
`output_throughput` 或逐请求 E2EL 数组。原始 JSON 保存了每条请求的
`output_lens[i]`、`ttfts[i]` 和 `itls[i]`。因此本卡只使用下列可复现代理：

```text
reconstructed_e2el_i = ttfts[i] + sum(itls[i])
effective_output_rate_proxy_i = output_lens[i] / reconstructed_e2el_i
```

单位为 output tok/s，越低表示该请求的端到端有效输出速率越差。该代理与
`serve.py` 恢复 request latency 的 timeline 口径一致，但不能冒充 benchmark
原生逐请求 `output_throughput`。也不能用 `output_len / 整轮 duration`、
`1/TPOT` 或 `1/TTFT` 替代它。

选择过程是：对同一数据行在 current-best 三轮中的代理值求均值，每档选择
三轮均值最低的数据行；同时归档这条数据的三轮绝对最低观测值。三档中，
按均值选择和按三轮任一单点最小选择恰好得到同一数据行。

## 后续小样本评估协议

1. 固定对象是上表三条原始数据行，不是把整轮聚合吞吐拆到单条，也不是
   C100 的前三行集合。不得修改原始数据集或官方评测脚本；生成临时单行
   fixture 时必须逐字节复制并核对行 SHA，且记录 fixture 生成命令和 SHA。
   current-best与candidate在某一上下文档的比较必须使用**同一条原始数据**；
   prompt、原始JSON字段、输出上限和行SHA任一不同，该档比较立即无效。
2. current-best baseline 和 candidate 在同一物理 HCU、相同服务配置、并发、
   请求参数和数据顺序下 fresh paired/interleaved 重放三条 fixture。每档都以
   同一公式重算三轮或预注册长窗均值。只要candidate在**任一上下文档**严格
   高于同窗current-best，就标记`PROMISING-ONE-BAND`，说明该方向有深入优化
   价值，可以继续调优并进入完整`all`评估；其余两档无论正负都必须原样记录。
   历史均值和历史最低观测值用于身份与漂移审计，不能单独替代fresh baseline。
   对档位`b`的唯一合法比较为
   `Δ_b=r(candidate, D_b)/r(current_best, D_b)-1`，两侧的`D_b`必须是同一
   冻结数据行。用另一条请求得到的candidate数值去超过本卡历史最低值，不算
   提升，也不能触发`PROMISING-ONE-BAND`。
3. 只有结果文本和 output length 可比较时，才能直接 paired 比较该代理。
   无损候选要求 output length、全文和 finish reason exact。允许有损的低精度
   候选若输出漂移，必须显式报告，不能把变化后的 `output_len/E2EL` 当作等价
   paired 胜利；随后仍须按计划用固定 accuracy 的实际 `K` 判断综合分。
4. 三条中至少一条严格正向且正确性门通过，即可扩展到完整、未修改的`all`；
   这只表示“值得深入优化”，不表示候选已经整体晋级或可以替换baseline。
   版本优劣仍由完整可比`all`的`T_mid=(global max+global min)/2`判断，并继续
   执行full×3、SLA、accuracy和综合分闭环。单请求proxy不替代正式aggregate
   `output_throughput`，单档收益也不能抹去其它档的回退记录。
5. 当前 `run_throughput.sh <band> 1` 只能取第一条。`4-8K` 第 38 条和
   `8-16K` 第 2 条必须用经 SHA 核验的临时单行 fixture 或新增不改变默认行为的
   offset/fixture 开关；不得用“前 N 条”冒充指定行。
